## Context

Web application for a financial institution, constantly evolving with multiple teams working in parallel. The central challenge: allowing independent squads to ship features without conflicts while keeping visual consistency and code quality at scale.

## My role

As a Senior Front-end Developer, I work on building and evolving the front-end architecture, developing features and maintaining the Design System that powers the entire application's interface.

## Key challenges

- Coordinating the evolution of a **Micro Frontend architecture with Module Federation**, where independent modules must coexist without breaking each other.
- Ensuring **visual consistency** across modules built by different teams.
- Keeping **code quality** high in a financial product, where regressions are costly.

## Solutions implemented

- Built interfaces with **React and TypeScript** within the Micro Frontend architecture, respecting the contracts between modules.
- Created and evolved **reusable components** aligned with the Design System, with tokens standardized via **Style Dictionary**.
- Documented components in **Storybook**, making reuse and team alignment easier.
- Implemented **tests with Jest** with coverage tracking, plus linting integrated into the quality workflow.
- Integrated with **REST APIs documented via Swagger**, fully handling loading, error and success states.
- Used **Docker, Nginx and Git** in the development, versioning and delivery workflow.

## Results

- Teams can evolve their modules independently, with the Design System ensuring visual consistency across all of them.
- Documented and tested components reduce rework and make onboarding new developers easier.
- The quality workflow (tests + coverage + lint) prevents regressions in a domain where stability is critical.
